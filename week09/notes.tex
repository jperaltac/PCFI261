\begin{frame}{Una capa densa como operacion matematica}
Una capa densa recibe un vector de entrada $\bm{x}\in\mathbb{R}^{n}$ y produce
\[
\bm{h}=\phi(W\bm{x}+\bm{b}),
\]
donde $W$ contiene pesos, $\bm{b}$ contiene sesgos y $\phi$ es una activacion no lineal.

\begin{block}{Lectura computacional}
Cada capa mezcla componentes del arreglo de entrada y aplica una no linealidad. Al encadenar capas, la red aprende representaciones internas utiles para la tarea.
\end{block}
\end{frame}

\begin{frame}{Entrenamiento, validacion y test}
\begin{itemize}
    \item \textbf{Train}: ajusta los pesos del modelo.
    \item \textbf{Validation}: ayuda a elegir arquitectura, hiperparametros y momento de detencion.
    \item \textbf{Test}: entrega una estimacion final del rendimiento fuera del entrenamiento.
\end{itemize}

\begin{alertblock}{Buena practica}
No mirar test hasta el final. Si usamos test para decidir arquitectura, deja de ser una evaluacion independiente.
\end{alertblock}
\end{frame}

\begin{frame}{Caso de estudio: Pima Indians Diabetes}
\justifying
El conjunto de datos contiene 768 registros clinicos tabulados con 8 variables de entrada y una salida binaria \texttt{Outcome}.
\begin{itemize}
    \item Entradas: embarazos, glucosa, presion arterial, pliegue cutaneo, insulina, BMI, funcion de pedigree diabetico y edad.
    \item Salida: clase 0 o 1 asociada al resultado observado en el dataset.
    \item Tamano: pequeno, ideal para experimentar en clase sin hardware especial.
\end{itemize}

\begin{alertblock}{Advertencia}
El notebook estima probabilidades segun un modelo entrenado con este dataset. No entrega diagnosticos medicos ni reemplaza evaluacion profesional.
\end{alertblock}
\end{frame}

\begin{frame}{Preguntas para guiar la discusion}
\begin{itemize}
    \item \textbf{Arquitectura}: una red mas grande siempre mejora el resultado?
    \item \textbf{Datos}: que variables tienen ceros que parecen datos faltantes?
    \item \textbf{Metricas}: accuracy basta para tomar decisiones en salud?
    \item \textbf{Umbral}: como cambia el balance entre falsos positivos y falsos negativos?
    \item \textbf{Etica}: por que una probabilidad del modelo no es un diagnostico?
\end{itemize}
\end{frame}

\begin{frame}{Actividad: datos propios o familiares}

\begin{alertblock}{Limites}
No registrar nombres ni identificadores. No presentar el resultado como diagnostico. Si el resultado genera preocupacion, la accion correcta es consultar a un profesional de salud.

\begin{block}{Discusion cientifica}
El ejercicio sirve para hablar de extrapolacion, sesgo del dataset, incertidumbre, causalidad y responsabilidad al comunicar resultados de modelos.
\end{block}
\end{frame}

\begin{frame}{Experimento opcional con GPU}
\begin{itemize}
    \item Pima es pequeno: una CPU basta.
    \item Para justificar GPU se incluye una celda opcional con datos sinteticos de alta dimension y una red con millones de parametros.
    \item En Colab se puede comparar CPU versus GPU cambiando el entorno de ejecucion.
\end{itemize}

\begin{block}{Mensaje docente}
La GPU no hace mas inteligente al modelo. Acelera operaciones matriciales grandes cuando el problema y la arquitectura lo justifican.
\end{block}

    \item En problemas de salud, la interpretacion y la comunicacion responsable son parte del modelamiento.
\end{itemize}
